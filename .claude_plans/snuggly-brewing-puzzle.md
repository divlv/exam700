# Кнопка «AI»: проверка вопроса моделью в Azure OpenAI, попап, сохранение и раздел «AI-проверки»

## Context

Кнопка «AI» отправляет в модель, развёрнутую в Azure, **PNG-картинку вопроса**, получает ответ в виде красивого HTML (эмодзи, небольшая графика) и показывает его в попапе. Ответ сохраняется в БД, и повторное нажатие на том же вопросе **не делает второго платного запроса**. Плюс, по вашим уточнениям:

- запросы к модели идут с **`reasoning effort = high`**;
- пока идёт запрос, в попапе **индикатор загрузки**;
- новый раздел программы **«AI-проверки»**: компактная таблица всех вопросов, которые отправлялись на проверку, с кратким описанием каждого и ответом модели; сортировка по дате и по вопросу.

Принятые решения:
- Модель — развёртывание **`gpt-6.1-sol`** в вашем Azure OpenAI. Проверить это имя я не могу: список моделей по ключу отдаёт каталог региона (489 базовых моделей), а не ваши развёртывания. Поэтому первым шагом реализации — один пробный живой запрос.
- В запросе только картинка вопроса.
- Клиент и формат — как в `sample-code/`: пакет `openai`, `OpenAI(api_key=…, base_url="https://<host>/openai/v1/")`, **Responses API**, `model` = имя развёртывания (отличие от общего примера `chat.completions` в `CLAUDE.md` — по вашему указанию на `sample-code/`). Сверено по типам установленного SDK: картинка — `{"type": "input_image", "image_url": "data:image/png;base64,…", "detail": …}`; effort — `reasoning={"effort": "high"}` (значение допустимо); структурированный ответ — `text={"format": {"type": "json_schema", "name": …, "strict": true, "schema": …}}`.

Что уже проверено: `AZURE_OPENAI_ENDPOINT` и `AZURE_OPENAI_API_KEY` в этом окружении заданы (значения нигде не выводились), эндпоинт отвечает HTTP 200; у вас глобально `openai 2.54.0` (на PyPI уже 3.x, под неё примеры не проверены) — закрепим **`openai>=2.54,<3`**.

## Как это выглядит

1. В шапке вопроса рядом с «Вопрос некорректный» — кнопка **«✨ AI»**; такая же у каждого вопроса в разборе сессии.
2. Клик открывает попап (`<dialog>`): заголовок, крестик и **индикатор загрузки** — вращающийся спиннер, надпись «Модель разбирает вопрос…» и счётчик секунд («42 с»). Модель с высоким effort может думать минуты; попап не закрывается сам.
3. Готовый ответ показывается в изолированном `<iframe>`; внизу пометка «gpt-6.1-sol · дата · сохранено» и, если ответ из кэша, без ожидания.
4. Повторный клик по тому же вопросу (в любой сессии, после перезапуска пода) — мгновенно из БД.
5. Закрыли попап или телефон «уснул» во время запроса — ничего не теряется: запрос работает на сервере, при следующем нажатии попап снова покажет «идёт запрос» и подхватит результат, не плодя второй платный вызов.
6. Не настроено — кнопка серая с подсказкой. Ошибка — понятное сообщение и «Повторить»; неудача не кэшируется.

### Раздел «AI-проверки» (`/ai`, пункт в главном меню «🤖 AI-проверки»)

Компактная таблица, по строке на вопрос:

| Дата | Вопрос | О чём вопрос | Ответ AI | Токены |
|---|---|---|---|---|

- **«О чём вопрос»** — краткое описание в одну строку (до ~140 символов): у вопроса нет текста, только картинка, поэтому описание **генерирует сама модель** тем же запросом (поле `summary` структурированного ответа) и мы его сохраняем. **«Ответ AI»** — короткий итог («B», «A, D», «Private peering; Microsoft peering»), тоже поле структурированного ответа.
- Сортировка: клик по заголовку «Дата» или «Вопрос» меняет порядок (▲▼), по умолчанию — новые сверху. Сортировка серверная (ссылки `?sort=date|question&dir=asc|desc`), работает и без JS.
- Клик по строке открывает тот же попап с полным ответом; на этой странице в попапе есть сворачиваемый блок «Показать вопрос» с картинкой вопроса, чтобы не искать, о чём шла речь. Итого: «Проверено вопросов: N · токенов всего: …».
- На телефоне таблица превращается в карточки (уже существующая техника `table.responsive`).

## Архитектура — новый доменный модуль `api/modules/aiassist/`

- `api.py` — `ensure_schema`, `is_configured()`, `start(question)` (идемпотентно: из кэша / уже идёт / запускает), `status(question_id)`, `get_answer`, `list_answers(sort, direction)`; исключения `AiNotConfigured`.
- `repo.py` — таблица `ai_answers`: `question_id` PK, `html`, `summary`, `answer`, `model`, `effort`, `prompt_version`, `response_id`, `input_tokens`, `output_tokens`, `created_at`. Версия схемы своя (`aiassist` v1) через `shared.apply_migrations`. **Без FK и каскада:** «Сбросить статистику» ответы AI не удаляет — они платные.
- `services.py` — задача выполняется в фоновом потоке (`ThreadPoolExecutor`, 2 воркера) со **своим** соединением SQLite (соединение запроса к этому моменту закрыто). Реестр задач в памяти под блокировкой: на вопрос не больше одной задачи, поэтому двойной клик или две вкладки дают **один** платный вызов. Состояния: `done` / `running` (+ время старта) / `error` (последнее сообщение, хранится в памяти). Сервер однопроцессный (`--workers 1`), памяти хватает.
- `internal/_client.py` — конфиг из окружения: `AZURE_OPENAI_ENDPOINT` (проверка как в примере: https, `*.openai.azure.com`, путь `/openai/v1`), `AZURE_OPENAI_API_KEY`, `AZURE_OPENAI_DEPLOYMENT` — **без значения по умолчанию**, чтобы не зашивать имена ваших ресурсов в публичный репозиторий. Вызов: `responses.create(model=<deployment>, instructions=…, input=[user: input_text + input_image(detail="high")], reasoning={"effort": "high"}, text={json_schema}, max_output_tokens=…, store=False, timeout=600)`. `store=False` — картинки не хранятся на стороне сервиса. Повторы — встроенные в SDK (`max_retries=2`, только 429/5xx/сеть). Ошибки приводятся к безопасным сообщениям, ключ вырезается (как `classify_openai_error` в примере). Если модель вернула не JSON — берём текст как HTML, `summary` пустой, а не падаем.
- `internal/_prompt.py` — инструкция на русском: эксперт AZ-700; на картинке вопрос (возможны HOTSPOT / drag-and-drop / кейс); определить правильный ответ самостоятельно; заполнить `summary`, `answer` и `html` — **только фрагмент** из заданного набора CSS-классов (вердикт, разбор вариантов, ключевая идея, где почитать); честно сказать, если картинка нечитаема или данных не хватает; в дампах ответы бывают неверными. Версия промпта хранится с ответом.
- `internal/_sanitize.py` — **`nh3`** (на PyPI 0.3.7) с белым списком: безопасные теги и атрибуты текста и таблиц + маленькое подмножество inline-SVG для «небольшой графики» (`svg, g, path, circle, rect, line, polyline, polygon, ellipse, text, tspan, title`; без `style`, `href`, `use`, `image`, `foreignObject`, скриптов, обработчиков событий, внешних ссылок и картинок). Санитизация при сохранении.

### Безопасность ответа модели

Это недоверенный HTML (в картинке вопроса может быть текст-инъекция). Три слоя: санитизация при сохранении; показ только через `GET /ai/{id}/view` в `<iframe sandbox>` **без** `allow-scripts` и `allow-same-origin`; заголовки `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; img-src data:` и `X-Content-Type-Options: nosniff`. `summary` и `answer` выводятся в таблице как обычный текст (автоэкранирование Jinja).

## Веб-слой

- `web/routes/ai.py` (все за `require_login`): `POST /ai/{question_id}` → запускает/подхватывает задачу, ответ JSON `{state: done|running|error, …}` (404 нет вопроса, 503 не настроено); `GET /ai/{question_id}/status` — опрос; `GET /ai/{question_id}/view` — страница-обёртка с нашим CSS (карточки, бейджи ✅/❌, таблицы, светлая/тёмная тема) вокруг сохранённого фрагмента; `GET /ai` — раздел «AI-проверки» (`sort`, `dir`).
- Шаблоны: `_ai_dialog.html` (общий попап) в `exam_question.html`, `session_detail.html` и новой `ai_list.html`; пункт меню в `menu.html`.
- `app.js`: `initAiButtons()` — клик → `showModal()`, `POST`, опрос статуса каждые 2 с до `done`/`error` (потолок ~12 мин) со счётчиком секунд, затем `iframe.src = /ai/{id}/view`. **Горячие клавиши (Пробел, 1/2/3, M, Esc→«прервать») игнорируются, пока открыт попап**, иначе Esc, закрывающий попап, ещё и прерывал бы тест.
- `app.css`: кнопка, диалог (на ≤768px — на весь экран), спиннер.
- `web/main.py`: в стартовом логе `ai=on/off deployment=…` (без ключа).

## Конфигурация и деплой

- `requirements.txt`: `openai>=2.54,<3`, `nh3>=0.3`.
- Переменные: `AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_API_KEY`, `AZURE_OPENAI_DEPLOYMENT`. В k8s — три необязательных ключа в Secret `az700-secrets` (`optional: true`: без них под стартует, AI выключен). Все три в Secret, а не в манифесте — репозиторий публичный. Обновляю `az700-secret.example.yaml` (плейсхолдеры), `az700-app.yaml` (`secretKeyRef`) и существующий `docs/deploy-k3s.md` (как заполнить, строка диагностики «AI не настроен / таймаут», для `docker run` — три `-e`). Исходящий HTTPS пода к `*.openai.azure.com` в кластере не ограничен (NetworkPolicy нет).
- Логирование по правилам репозитория, с оговоркой: пишу модель, effort, id вопроса, размер и sha256 картинки, версию промпта, задержку, токены, id ответа, текст ответа (DEBUG). **Не пишу** ключ, заголовки авторизации и base64 картинки (мегабайты) — сознательное отступление от пункта «логировать полное тело запроса», иначе нарушается запрет на секреты.

## Тесты

Модуль (фейковый клиент, без сети): кэш-попадание — вызова нет; промах — ровно один вызов и запись `summary/answer`; 5 одновременных `start` на один вопрос — один вызов; во время работы `status` = `running`; сбой — ничего не записано, `error` с понятным текстом без ключа; не настроено; не-JSON ответ модели не роняет; валидация эндпоинта; миграция идемпотентна; «Сбросить статистику» не трогает `ai_answers`; `list_answers` — сортировка по дате и по вопросу в обе стороны. Санитайзер: вырезает `<script>`, `onerror`, `javascript:`, `<iframe>`, внешние `<img src=http…>`, `style`; оставляет разрешённые теги и безопасный SVG. Веб (подмена сервиса): логин обязателен, коды 200/202/404/503, заголовки CSP на `/view`, кнопка на экране вопроса и в разборе (активная/серая), страница `/ai` — строки, описание, сортировка по заголовкам, пустое состояние, пункт меню.

По одному запросу на вопрос. Смотрю качество HTML, `summary`/`answer`, задержку и расход токенов.
3. Браузер (headless Edge, как раньше) на копии данных с реальными ответами: клик «AI» → спиннер со счётчиком → ответ; второй клик мгновенный (в логе нет второго вызова); Esc закрывает попап и не прерывает тест; раздел «AI-проверки»: таблица, сортировка по обоим заголовкам, открытие ответа; 390 px — попап на весь экран и карточки без горизонтальной прокрутки; скриншоты.
4. Деплой: `git push`; вам — добавить три ключа в Secret, `k3s kubectl apply`, `drestart az700`; в логе пода `ai=on`.

## Вне объёма

Кнопка «спросить заново» (платная, вы её не просили), потоковый вывод ответа, дашборд расходов с ценой в деньгах (токены показываем, цену — нет), вопросы вне каталога, картинка ответа из источника в запросе, нарезка очень высоких картинок на части (нужен Pillow; только если живой тест покажет, что иначе нечитаемо), правки `sample-code/` (он в `.gitignore`).
