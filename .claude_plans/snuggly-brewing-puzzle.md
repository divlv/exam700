# Настройка «Алгоритм выбора вопросов»: адаптивный и случайный

## Context

Сейчас вопросы выбираются одним способом: из 10 случайных доступных побеждает ещё не отвеченный, иначе тот, на который чаще всего отвечали неправильно (`_choose_next` в `api/modules/examsession/services.py`). Нужна ещё и **чисто случайная** выборка по всей базе. Алгоритм переключается в настройках в любой момент, следующий вопрос выбирается по выбранному, а на экране вопроса маленькая отметка показывает, какой алгоритм сейчас действует.

## Решения

**Названия** (вы просили придумать):
- `adaptive` — «🎯 Адаптивный»: как сейчас. Подсказка: «Сначала вопросы, на которые вы ещё не отвечали, потом те, где больше всего ошибок».
- `random` — «🎲 Случайный»: равновероятно любой легитимный вопрос, то есть доступный (не помечен некорректным и в источнике есть ответ). Внутри одной сессии вопросы не повторяются, как и сейчас; быстрый вопрос выбирает из всей базы. История ответов не учитывается.
- По умолчанию «Адаптивный», поведение без вашего участия не меняется.

**«В любой момент».** План сессии набирается заранее при старте и лежит в БД (`session_questions`), поэтому новая настройка сама по себе не повлияла бы на идущую сессию. Чтобы «следующий вопрос» действительно выбирался новым алгоритмом, при смене алгоритма **оставшиеся вопросы идущей сессии выбираются заново**: заменяются только вопросы после текущего, которые ещё не оценены и не отложены. Открытый сейчас вопрос, уже оценённые и отложенные остаются (подменять вопрос, который вы уже читаете, неправильно). Сохранили ту же настройку (например, меняли только размер сессии) — план не трогается. Замена вопроса, помеченного некорректным, тоже идёт по текущему алгоритму.

**Отметка на экране вопроса** показывает **текущую настройку**, а не то, каким алгоритмом выбран именно этот вопрос: сразу после переключения открытый вопрос ещё «от прежнего» алгоритма, это объясню в подсказке к отметке.

## Изменения

**`api/modules/examsession/services.py`** (миграции БД нет: настройка лежит в существующей таблице `app_settings`, ключ `selection_algorithm`):
- константы `SELECTION_ADAPTIVE`, `SELECTION_RANDOM`, `SELECTION_ALGORITHMS`, по умолчанию адаптивный;
- `_choose_next(conn, exclude, rng, algorithm)`: для `random` одна строка, `source.choice(candidates)` по тому же списку доступных без `exclude`; адаптивная ветка не меняется (её 13 тестов остаются как есть);
- `get_selection_algorithm(conn)` (неизвестное значение в БД даёт запасное значение и предупреждение в лог, как у `get_default_question_count`) и `set_selection_algorithm(conn, algorithm, rng=None) -> int` (неизвестное значение: `ValueError`; при смене пересобирает остаток идущей сессии и возвращает, сколько вопросов заменено);
- `SessionRunner.redraw_upcoming()`: берёт неоценённые и неотложенные вопросы после текущего, исключает из выбора всё остальное, что уже в плане, и заменяет каждый через существующий `repo.replace_plan_question`; запасной вариант «оставить прежний», если выбирать не из чего;
- `start_session` и `SessionRunner.flag_broken` читают текущий алгоритм в момент выбора.

**`api/modules/examsession/api.py`**: экспорт новых констант и двух функций.

**Веб:**
- `web/routes/settings.py`: поле `selection_algorithm` необязательное (старые отправки формы без него остаются рабочими; неверное значение игнорируется), после сохранения сообщение «Следующие вопросы идущей сессии выбраны заново: N», если что-то заменилось;
- `web/templates/settings.html`: группа из двух радиокнопок с названием и подсказкой (готовые стили `.option`); общий для настроек и экрана вопроса словарь подписей ставится Jinja-глобалом в `web/templating.py`, чтобы формулировки были в одном месте;
- `web/routes/exam.py`: `_render_question` получает текущий алгоритм (у всех четырёх вызывающих уже есть `conn`);
- `web/templates/exam_question.html`: рядом с «№N в наборе» маленький бейдж «🎯 Адаптивный» / «🎲 Случайный» (также у быстрого вопроса), в `title` пояснение;
- `web/static/app.css`: нейтральный `.badge-muted` и подпись группы `.field-title`.

**Документы:** `CONTEXT.md` (термины **Selection algorithm**, **Adaptive**, **Random**), `CONTINUITY.md`.

## Тесты

- Модуль (`tests/modules/examsession/`, рядом с `test_selection.py`): по умолчанию адаптивный, round trip, неверное значение отвергается, битое в БД даёт запасное; случайный **не** смотрит в историю (вопрос без ответов не побеждает, выбранные по сидам охватывают всю базу), не выбирает помеченные некорректными и без ответа в источнике, сессия из N даёт N разных вопросов, быстрый вопрос работает; замена после «Вопрос некорректный» идёт по текущему алгоритму; **смена посреди сессии**: заменяются только вопросы после текущего, оценённые, отложенные и текущий остаются, размер и уникальность плана сохраняются, результат сохранён в БД (виден после `resume_session`), та же настройка план не трогает, без активной сессии и без оставшихся вопросов смена безопасна.
- Веб: радиокнопки отражают сохранённое, сохранение «Случайный» переживает перезагрузку, неверное значение игнорируется, старая форма без поля работает; бейдж на экране вопроса меняется после переключения прямо во время сессии, у быстрого вопроса он тоже есть; сообщение о числе заменённых вопросов.
- Полный прогон: сейчас 328 passed, 29 skipped.

## Проверка вживую (временные файлы только в рабочей папке сессии, потом удалить)

1. **«Реально ли random»** на копии вашей реальной БД (297 доступных, около 234 ни разу не отвеченных): 2000 выборов одного вопроса в каждом режиме. Адаптивный выбирает ещё не отвеченный почти всегда (раньше измерено 2000 из 2000); случайный должен давать долю уже отвеченных около 21% (63 из 297), и частоты по вопросам без перекоса.
2. Локальный `uvicorn` на копии данных, headless Edge (как раньше): на странице настроек два варианта, сохранение, бейдж на экране вопроса меняется после переключения прямо посреди сессии, текст сообщения о пересборке; вёрстка на 390 px без горизонтального скролла, скриншоты.
3. Уборка: сервер, браузер, копия БД.
