# Широкий просмотр на десктопе + умный выбор вопросов по журналу ответов

## Context

Две правки по запросу:

1. На десктопе окно с картинкой вопроса «узкое, как на телефоне», и в нём появляется горизонтальная прокрутка.
2. Выбор вопросов для сессии должен учитывать, как вы отвечали раньше: неотвеченные — в первую очередь, затем те, где было больше всего неправильных ответов.

Принятые решения (из ваших ответов): **«Сброс статистики» очищает и журнал**; «хуже всего» = **больше всего неправильных ответов**.

## Часть 1. Просмотр картинки на десктопе

### Причины (найдены в коде)

- **Узкое окно.** `.page { max-width: 720px }` (`web/static/app.css:95`) действует на все страницы, в том числе на экран экзамена. Картинка вопроса имеет ширину 1355 px и на десктопе ужимается до ~700 px (≈50%) — мелко, как на телефоне.
- **Горизонтальная прокрутка.** `fitToWidth` (`web/static/app.js`) берёт `scroll.clientWidth - 4` в момент, когда вертикальной полосы прокрутки у окна ещё нет. После применения ширины картинка становится высокой, у окна (`overflow: auto; max-height: 70vh`) появляется вертикальная полоса (на десктопе она занимает ~15 px, на телефоне полосы накладываются и места не занимают — поэтому там не видно), `clientWidth` уменьшается, и картинка оказывается шире окна на ~11 px → горизонтальный скролл.

### Изменения

- `web/templates/base.html` — `<main class="page{% block page_class %}{% endblock %}">`; `exam_question.html` задаёт ` page-exam`. Остальные страницы не затрагиваются.
- `web/static/app.css`:
  - `@media (min-width: 769px) { .page-exam { max-width: 1440px; } }` — картинка 1355 px + поля помещаются в 100%. Телефоны и планшеты не меняются (там контейнер и так на всю ширину).
  - `.image-viewer-scroll { scrollbar-gutter: stable; }` — место под вертикальную полосу резервируется заранее, ширина окна не «прыгает».
- `web/static/app.js`, `fitToWidth`:
  - масштаб «по ширине» не больше 1.0 (на широком экране картинка не растягивается и не мылится; по центру);
  - после применения ширины проверка `scroll.scrollWidth > scroll.clientWidth`; если полоса прокрутки всё же появилась — один повторный расчёт по новой `clientWidth`. Работает и в браузерах без `scrollbar-gutter`.
- Высоту окна (`max-height: 70vh`) и мобильную раскладку (липкая панель, зум) не трогаем.

### Тесты и проверка

- Тест `tests/web/test_exam_flow.py`: на странице экзамена есть класс `page-exam`; на меню его нет.
- `node --check web/static/app.js`.
- **Визуально я проверить не могу** (нет браузера в сессии) — после деплоя откройте экзамен на десктопе: при окне 1920 px картинка в 100% без горизонтальной полосы, при окне ~1280 px — по ширине и тоже без неё; на телефоне всё как раньше.

## Часть 2. Выбор вопросов по журналу ответов

### Журнал

Журнал уже ведётся: каждый ваш ответ сохраняется в `session_answers` (вопрос, оценка, сессия, время), поэтому **новых таблиц и миграции не нужно**. История вопроса = все его ответы во всех сессиях (включая прерванные), например `54: 1 правильно, 2 частично, 3 неправильно`. Сброс сессии/всей статистики каскадно удаляет ответы, значит и журнал — после сброса все вопросы снова считаются неотвеченными (ваше решение). Журнал начинает работать сразу на уже накопленных данных (10 сессий, 71 ответ).

### Алгоритм выбора одного вопроса

1. Кандидаты — доступные вопросы, которых ещё нет в этой сессии.
2. Случайно берём **10** кандидатов (если осталось меньше — все оставшиеся).
3. Из этих десяти:
   - если есть вопросы **без единой записи в журнале** — выбираем любой из них случайно;
   - иначе выбираем вопрос с **наибольшим числом неправильных ответов**; при равенстве — случайный из равных.
4. Правильные и частичные между собой не различаются (как вы выбрали), поэтому, например, вопрос «10 раз правильно» и вопрос «1 раз частично» при 0 неправильных — ничья, решает случай.

### Как применяется

- **Начало сессии на N вопросов** — шаг выше повторяется N раз (выбранные исключаются). Это равносильно выбору «по ходу»: вопрос в рамках сессии не повторяется, поэтому его история за время сессии не может измениться, а ответы в сессии на уже выбранные вопросы журнал для оставшихся не меняют. Зато план по-прежнему целиком хранится в БД (`session_questions`), и всё, что уже сделано для телефона — возобновление сессии, предзагрузка следующей картинки, счётчик «из N», — работает без изменений.
- **Замена вопроса при пометке «некорректный»** — берётся тем же алгоритмом (сейчас `flag_broken` использует простой случайный выбор).
- `questionbank.sample_questions` остаётся как есть (публичный API со своими тестами), просто `examsession` им больше не пользуется.

### Изменения в коде

- `api/modules/examsession/domain.py` — dataclass `QuestionHistory(correct, partial, incorrect)` со свойством `attempts`.
- `api/modules/examsession/repo.py` — `answer_history(conn, question_ids) -> dict[int, QuestionHistory]`: один запрос `GROUP BY question_id, grade` по ≤10 id.
- `api/modules/examsession/services.py` — константа `SELECTION_WINDOW = 10`; `_choose_next(conn, exclude, rng)`; `start_session` строит план циклом из N вызовов (ошибки «мало вопросов» — `NoQuestionsAvailable` с теми же сообщениями); `SessionRunner.flag_broken` берёт замену через `_choose_next` (вместо `sample_questions` + `except ValueError`; `None` = «заменить нечем»).
- Веб-слой, шаблоны и схема БД не меняются. Деплой: `git push` → CI → `drestart az700`.

### Тесты (новый файл `tests/modules/examsession/test_selection.py`, свой небольшой fixture с пустой БД; историю сидим прямыми вставками в `sessions`/`session_answers`)

- неотвеченный вопрос всегда выигрывает у отвеченных (пул ≤ 10, много seed'ов);
- среди отвеченных побеждает вопрос с наибольшим числом неправильных; ваш пример: вопрос 54 (1/2/3) против вопроса 128 (3 правильно) → выбирается 54;
- равенство: из равных выбираются оба варианта (по seed'ам) и никогда посторонний; из нескольких неотвеченных — любой из них, отвеченные не выбираются;
- окно: запись обращений к `rng.sample` показывает `k == 10` при большом пуле и `k == остаток`, когда осталось меньше 10;
- сессия на N вопросов — без повторов, ровно N; пул меньше N → `NoQuestionsAvailable`;
- замена при пометке «некорректный» берёт худший из оставшихся (4 вопроса: один неотвеченный, он выбран и помечен → замена — вопрос с наибольшим числом неправильных);
- после `reset_all_sessions` бывший «худший» вопрос снова неотвеченный и перестаёт выбираться всегда первым.

Существующие тесты (`test_session.py`, веб) от конкретных вытянутых id не зависят — должны проходить без правок.
